DeployedHackathon build · July to October 2026

Whetstone

Coding exercises that carry proof they can be solved. An AI writes each exercise, and a sealed sandbox has to pass it before any student sees it.

The problem

A language model that writes a coding exercise has no way to know whether it can be solved. It ships a broken problem with the same confidence as a good one. An instructor pastes twenty generated problems into a worksheet, three can't be solved, and a student loses an evening on problem 14 believing the mistake is theirs.

What I built

A generate-and-verify loop. The model writes a candidate exercise, a reference solution and the tests that will judge it. A locked-down Docker container runs the solution against those tests with pytest. A pass publishes the exercise. A fail goes into a discard log with the reason attached.

Django and PostgreSQL store every candidate, kept or discarded, and the discard rate is a query, never a stored number. Celery queues generation runs. A Flutter Web front end shows the counts, the discard log and the published exercises.

Decisions I made

  • I put the discard log in the product. It's the quickest way to show a teacher why the kept exercises can be trusted.
  • I sealed the judge after thinking through what model-written code could do to the host: no network, read-only filesystem, every Linux capability dropped, a non-root user, a 64-process cap, 512 MB of memory and a hard kill at 10 seconds, with a 15-second backstop in the parent process.
  • I froze the API contract for the Flutter client. New fields are fine; renaming or removing one requires a /api/v2.
  • Midway through, the hackathon credits turned out to be Codex credits rather than API credits. I moved generation into Codex and kept the sandbox as the only judge, so the product didn't change.

LiveFull-stack web app · April 2026

Oloonkerin Management

An admin system for a fleet and machinery business: vehicles, drivers, fuel, maintenance, projects and payroll in one place, behind a login.

The problem

A business that runs vehicles and heavy machinery across several projects needs one record of who drove what, how much fuel it used, what broke, which project it served and who gets paid at the end of the month. Spreadsheets split that record across people and files.

What I built

A login-protected admin app with nine modules. The back end is an async FastAPI service on SQLAlchemy 2 and asyncpg, with a versioned REST API under /api/v1, one endpoint module per domain, Pydantic schemas for each domain, Alembic migrations for schema changes and a seed script for demo data.

The front end is React 19 and TypeScript on Vite, styled with Tailwind CSS 4. Each domain has its own typed API module on a shared Axios client. An auth context and a protected route send anyone who isn't signed in back to the login page.

Highlights

  • JWT authentication with bcrypt-hashed passwords (python-jose and passlib).
  • The back end ships in Docker on Render; the front end deploys on Vercel. Configuration comes from the environment, with an .env.example checked in.
  • Three Alembic migrations take the schema from an empty database to the full model, so any environment can be rebuilt from scratch.

CompleteDesktop application · Kenyatta University, SCO 200 · September to November 2026

Azani ISP Information System

Billing and operations software for an internet service provider that connects institutions, packaged as a one-click Windows installer.

The brief

An ISP needs to register institutions and their contact people, assess each site's readiness, order equipment, record installations, manage bandwidth plans, subscriptions and upgrades, take several kinds of payment, run a monthly billing cycle that fines and disconnects late payers, and report on all of it.

What I built

A Java 17 Swing desktop app on a 12-table MySQL database, layered as UI, services, DAOs and JDBC. Seven screens cover the dashboard, registration, site visits, subscriptions, payments, billing and reports. The services hold the business rules and have their own unit tests.

Then I made it easy to run. build.bat compiles the code, bundles a Java runtime with jpackage, copies in a MySQL 8.4 server preloaded with sample data and wraps everything in an Inno Setup installer. It needs no admin rights, no Java, no MySQL and no internet. The bundled database only runs while the app is open and only accepts connections from the same computer.

Decisions I made

  • The clerk can press “Run billing” twice without double-charging anyone. Idempotence comes from checking existing rows, so no extra state is needed.
  • Each billing rule is tagged in the code with the design decision it implements (D2a, D3a, D5a), so every rule traces back to the spec.
  • Billing can also run for a single institution, which lets tests check one account without touching any other row.
  • The README maps every startup error to its fix, from a port already in use to a database that won't start, so a marker never gets stuck.

In progressBack-end API · March 2026 to now

YelenImport

The API behind an online store for imported products, covering the catalogue, search, cart, quotes and orders.

What I built

A FastAPI service on PostgreSQL that handles sign-up and login, the product catalogue and search, the cart, favourites, quote requests, orders and contact messages. Routers stay thin: Pydantic schemas validate input, a services layer holds the business logic, and shared dependencies inject the database session and the current user. The core services have tests.

Security and configuration

  • OAuth2 password flow issuing JWTs (python-jose), with passwords hashed using bcrypt (passlib).
  • Settings and secrets load from the environment through pydantic-settings, never from code.
  • Interactive API docs come with every run at /docs, so a front-end developer can try each endpoint.

How I work

Four habits that show up in my code

Prove it runs before it ships

Whetstone publishes nothing its sandbox hasn't executed, and it keeps the failures on show. Azani's billing service is tested one institution at a time, so a test never disturbs real rows.

Take the setup step away

Azani installs in one click and carries its own Java and its own database. My deployed apps read their settings from the environment, with an example file in the repo.

Write the decision down

Billing rules carry decision IDs in the code. Whetstone's API contract is frozen in a file the front end can rely on. My READMEs say what went wrong and what I changed, not only what works.

Build for the people around me

Matatu commuters, schools, an ISP serving institutions, Kiswahili braille learners, and the KRA, eCitizen and KUCCPS errands my business handles for clients in Nairobi.
